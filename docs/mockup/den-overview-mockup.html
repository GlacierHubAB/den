Den · design mockup · Overview tab and missions

Overview: one project at a time, its agents, its code, its missions

Den knows every agent on the machine. Overview narrows that to one project: pick it, and the view shows the agents working in it, the state of its checkout, and the missions standing on it. Review follows the same pick. A mission is a standing goal, in Aimless's words a purpose in one sentence with constraints and a definition of done; you write the goal, the orchestrator decides how to run it: once, as a loop, as a fan-out across agents, or on a schedule.

2 · Writing a mission

You type the goal on the Overview command line. The orchestrator reads the project and the fleet and answers with a proposal card: the mission in one sentence, what done looks like, constraints it inferred, and the shape it picked with one line of reasoning. ^Y starts it; typing replies to refine it; ^N drops it. Nothing runs before ^Y.

3 · A mission, opened

Enter on a mission opens it: the fields, then its runs. A run is the orchestrator's dispatch for one pass, shown with the same cards the orchestrator chat uses, so nothing is retold. A loop shows its iterations, a schedule its ticks with the next one, a fan-out the lead and its children. Pause holds the next run; stop ends the mission and keeps its history.

Mission shapes, chosen by the orchestrator

ShapeRuns asPicked when
▶ onceone dispatch to one agent; done when it reports backa bounded task one agent can finish
↻ loopone agent iterates until done; paced by a signal (CI hook, a file, a timer) or by the agent's own judgement, like Claude Code's /loopa goal reached by repeated passes that need the same context
⇶ fan-outa lead agent with children in parallel, repeated until the lead says done; uses the hierarchyindependent parts that each fit one agent
⏲ scheduleDen fires a run on a cadence (every n minutes, daily at a time, or a cron line); each tick is a once or a fan-outa recurring chore with nothing to react to in between

Mission fields

FieldFrom
missionone sentence, the orchestrator's rewrite of what you typed; you can edit it
done whenan observable end state, or "standing" for a mission that never ends
constraintstags the orchestrator infers plus yours; they ride on every dispatch of the mission
shape · cadencedecided by the orchestrator with one line of reasoning; "make it a schedule" overrides
agentschosen per run from the fleet on this project; a spawn when nobody is free
stateproposed · running · waiting on you · paused · done · failed

Where it lives

ThingHow
projectsthe repositories agents' edited files live in (the Review loader already finds them) plus session folders that are checkouts; named by repo, keyed by root; the pick is remembered in config
missions~/.local/state/den/missions.jsonl: id, project root, text, mission, done when, constraints, shape, cadence, state, created, and a run log; restored on launch
runsdispatch cards tagged with the mission id, so the orchestrator chat, the mission view and the Fleet tree all show the same cards
schedulesDen's own ticker; at a tick it asks the orchestrator to run the mission, so nothing depends on an agent being open
loopsthe agent's own /loop where it pays off; otherwise the orchestrator re-dispatches when the agent reports back and the goal is not met
the proposala structured reply from the orchestrator (JSON in its stream, rendered as the card); the system prompt gets the mission vocabulary and the shapes
