Den · design mockup · agent hierarchies

Who directs whom: parents and children across every Den view

Claude Code sessions can message each other, so an agent can hand work to other agents, and those can hand work on. Den already knows every session on the machine; this shows the same fleet as a tree instead of a flat list, and carries the parent–child relation into the map, the orchestrator chat and the inbox, without a new data store. The reference image draws rigs as a wiring diagram; Den keeps the single-column habit of the Fleet view and only adds guides.

1 · Fleet view, agents as a tree

Each agent sits under whoever gave it its current task. Rows keep the three lines they have today. A parent's first line gains "directs n" and rolls up what its children need; agents nobody directs stay in their own section at the bottom. ← → fold a branch; ↑ ↓ walk the tree in order.

2 · The map, one lane per level

m in the Fleet view swaps the agents pane for a horizontal tree. The same cards Den already draws, left to right from you to the leaves, so a long chain of command reads as a line and the fan-out of each parent reads as a column. Nothing crosses. Esc or m goes back to the list with the same agent selected.

3 · Orchestrator chat, a card that fans out

When an agent the orchestrator dispatched hands work on, its card grows a sub-list: one line per child, in the child's colour, with its own brief and state. The parent's state rolls the children up, so "needs you" surfaces at the top even when it is three levels down. ^Y ^N answer it from here. Enter expands the parent; Enter on a child line expands that child's turn in place.
