Decisions to react to

  1. One inbox, not one tab per agent. Everything that needs a human answer lands in one stream, newest at the bottom, with single-key answers. Per-agent history stays in the agent's own terminal.
  2. Den never embeds terminals. Enter on an agent focuses its real Ghostty window through Hyprland. The detail pane only shows a tail. This keeps Den small and avoids rebuilding what herdr already does.
  3. Identity comes from agent-badge. Critter, role, task and the earlier trail are read from the badge's plugin store, so both tools agree on who an agent is.
  4. No @ means the orchestrator. @Name addresses one agent directly. Anything else goes to an orchestrator that can see all agents and relay on your behalf. It never acts on permissions without you saying so in the message.
  5. Hue only for status. Following Deepharness: white opacity ladder for everything, yellow for "needs you", green for finished, red for an agent that crashed or vanished.
  6. Review sends comments to the session that wrote the code. Every changed line is attributed from the transcripts (Edit, Write and Bash file changes), so a comment goes back to the agent that still holds the context, not to a fresh one. Lines no agent wrote stay grey and can only be kept as notes or handed to the orchestrator.
  7. The diff is git's, the attribution is Den's. Den shows the working tree against the base branch, so you review what is really on disk, and colours each line by the transcript hunk it came from.
  8. Other harnesses appear read-only. pi, Codex and friends show up as dim rows when detected, until an adapter exists. Claude Code is the only first-class harness in v1.

Names, tasks and limits shown are the real agent-badge records for the six Claude Code sessions running on this machine when the mockup was made.
